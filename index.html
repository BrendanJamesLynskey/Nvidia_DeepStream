NVIDIA DeepStream — Presentation Series

NVIDIA DeepStream

The streaming vision-AI SDK, presented for engineers. Eight deep-dive decks trace one continuous arc — from what DeepStream is and the GStreamer foundation it is built on, through the plugin toolbox, inference with TensorRT and Triton, multi-object tracking, the metadata graph and analytics, edge-to-cloud messaging, and finally building and deploying a production pipeline. Every deck answers the same three questions: what problem it solves, how the mechanism works, and why it matters when you build and operate real video-AI systems — with a hand-drawn diagram wherever a picture helps.

Presentations in This Series

The eight decks are ordered to build on one another — the big picture and the GStreamer/architecture foundation come first, then the plugin toolbox, then a deep dive into each subsystem, and finally how to build and ship it. Each deck also stands alone.

    The Big Picture →
    What DeepStream is and why it exists: turning many live video streams into real-time structured insight, hardware-accelerated end-to-end on NVIDIA. The canonical pipeline, the software stack, where it runs (Jetson to dGPU), and the use cases it serves.
    liveOverview & motivation
    GStreamer Foundations & the DeepStream Architecture →
    DeepStream is a set of accelerated GStreamer plugins. Elements, pads, caps negotiation and buffers; the NVDEC/NVENC/GPU/VIC/DLA hardware blocks; and the zero-copy NVMM / NvBufSurface memory model that keeps the whole pipeline on the GPU.
    liveFramework & memory model
    The Plugin Toolbox →
    A guided tour of the 40+ plugins grouped by role — input & decode, batching & routing (nvstreammux/nvstreamdemux), inference, analytics & CV, compositing & OSD, and output & messaging — mapped onto the reference deepstream-app pipeline.
    liveThe plugin set
    Inference — nvinfer, TensorRT & Triton →
    Primary vs secondary GIE; how nvinfer builds and caches TensorRT engines; the config-file anatomy; pre-processing, clustering and custom parsers; batching and interval; and when to reach for Triton via nvinferserver. Plus TAO pretrained models.
    liveRunning the models
    Multi-Object Tracking →
    Persistent object identity across frames with nvtracker and the composable NvMultiObjectTracker library — IOU, NvSORT, NvDCF and NvDeepSORT; Re-ID galleries and re-association; the YAML config; and single-view 3D tracking.
    liveIdentity over time
    Metadata & Analytics →
    The NvDsBatchMeta → frame → object → classifier hierarchy that carries meaning alongside the pixels; metadata pools and lifecycle; reading it in buffer probes (C and pyds); extending it with user meta; and the nvdsanalytics rule engine (ROI, line-crossing, overcrowding).
    liveThe data model
    Messaging, Smart Record & IoT →
    The last mile: nvmsgconv serialises event metadata to JSON/protobuf, nvmsgbroker ships it to Kafka / MQTT / AMQP / Azure IoT / Redis; smart-record captures event clips; bidirectional cloud-to-edge control; and the REST API for dynamic streams.
    liveEdge to cloud
    Building & Deploying →
    Four ways to build — config-driven deepstream-app, C/C++, Python (pyds), and Graph Composer / Service Maker; packaging with NGC containers, JetPack and Kubernetes; and performance tuning for maximum streams-per-GPU with the debugging tools to get there.
    liveConfig to production
How to read this series

Start at Part 01 for the big picture, then Part 02 for the GStreamer and memory foundation that everything else assumes. Parts 03–07 each take one subsystem — the plugin set, inference, tracking, the metadata graph, and messaging — and go deep. Part 08 pulls it together into how you actually build, containerise and tune a production pipeline. If you already know GStreamer, you can jump straight to the subsystem you need.
